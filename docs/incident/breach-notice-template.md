# 개인정보 유출 통지문 틀 (6-10)

> **사용 전 반드시 확인하세요.** 이 틀은 수업용 예시이며 법률 자문이 아닙니다. 통지 항목·방법·기한은 법 개정으로 바뀝니다.
> 실제로 쓰기 전에 [국가법령정보센터](https://www.law.go.kr)에서 **개인정보 보호법 제34조와 같은 법 시행령(통지 항목·방법, 신고 대상 기준)의 최신 조문**을 확인하고, 사고 전에 법무 검토를 받아 두세요.
> 아래 항목 구성은 2026-09-11 시행 개정(72시간 통지·신고, 유출 "가능성" 통지, 정보주체의 권리 행사 방법 안내)을 기준으로 했습니다.

## 언제, 누구에게

| 시계 | 근거 | 무엇을 |
| --- | --- | --- |
| 알게 된 뒤 24시간 | 정보통신망법 (침해사고 신고) | KISA 에 최초 신고. 모르는 것은 "조사 중"으로 쓰고 늦추지 않는다. 추가로 확인된 사항은 보완 신고 |
| 알게 된 뒤 72시간 | 개인정보 보호법 (유출 통지·신고) | 이용자 통지 + 개인정보보호위원회(또는 KISA) 신고. 유출 **가능성**만 확인돼도 해당 |
| 범위가 바뀔 때마다 | 같은 법 | 보완 신고, 새로 확인된 이용자에게 추가 통지 |

- 시계는 사고가 **일어난 때가 아니라 알게 된 때**부터 돈다. 6-9 대응 기록(`IR-YYYY-MMDD.log`)의 첫 시각을 그대로 쓴다.
- 통지 대상·항목은 DB 감사 로그로 특정한다: `ops/sql/breach_scope.sql` (`audit.read_events`).
- 신고 대상 기준(예: 1천 명 이상, 민감정보·고유식별정보, 외부의 불법 접근)은 **시행령 기준**이므로 최신 조문으로 확인한다.

## 이용자 통지문 (초안)

법이 정한 항목은 빠짐없이, 해당하지 않는 항목도 분명히 적는다. 확인 중인 내용은 "조사 중"으로 쓰고, 새로 확인되면 다시 알린다.

```text
[개인정보 유출 안내] {서비스 이름}

1. 유출된 항목: {예: 이름, 휴대전화번호, 배송지 주소} ({해당 없는 항목: 예: 비밀번호·결제 정보는 해당 없음})
2. 유출 시점과 경위: {YYYY-MM-DD ~ MM-DD}, {예: 서버 침입으로 회원 정보 일부가 조회됨} (확인 중인 내용은 "조사 중")
3. 피해를 줄이기 위해 하실 일: {예: 문자·전화 피싱 주의, 의심되는 연락은 고객센터로 확인, 비밀번호 변경}
4. 회사의 대응과 피해 구제 절차: {예: 서버 격리, 접근 경로 차단, 피해 신고 창구 운영}
5. 담당 부서와 연락처: {예: 개인정보보호팀 privacy@example.com, 고객센터 1588-0000}
6. 손해배상 청구·분쟁조정 신청 방법:
   - 손해배상 청구: {회사의 접수 창구·절차} (개인정보 보호법 제39조·제39조의2)
   - 분쟁조정 신청: 개인정보 분쟁조정위원회 (www.kopico.go.kr, 국번 없이 1833-6972) (같은 법 제43조)
7. 그 밖에 대통령령(시행령)으로 정하는 사항: {최신 시행령 확인 후 기입}
```

## 작성 점검

- [ ] 항목이 최신 법 제34조·시행령과 일치한다 (확인한 날짜: ______, 확인한 사람: ______)
- [ ] 유출 항목과 대상자가 감사 로그로 특정됐다 (추정이면 "가능성"으로 쓰고 범위를 넓게)
- [ ] 해당 없는 항목(비밀번호·결제 정보 등)을 분명히 적었다
- [ ] 연락처가 실제로 받는 창구다 (대량 문의에 대비한 인력·FAQ)
- [ ] 통지 방법(문자·이메일·서면 등)과 홈페이지 게시 여부를 시행령 기준으로 정했다
- [ ] 개인정보 보호책임자·법무 검토를 받았다
- [ ] 보낸 시각·대상 수·방법을 대응 기록에 남겼다
