수습이 끝나면 **두 주 안에** 회고한다. "누가 잘못했나"가 아니라 "**왜 그 일이 가능했나**"를 묻는다. 사람을 탓하면 사실이 숨는다.

## 3. 원인 → 개선 과제

원인마다 과제를 하나씩. 과제마다 **담당자·기한·완료 확인 방법**을 정한다.

| 원인 (왜 가능했나) | 개선 과제 | 관련 수업 | 담당 | 기한 | 완료 확인 |
| --- | --- | --- | --- | --- | --- |
| 예: root SSH 로그인 허용 | 키 인증만, root 로그인 금지 | 1-1 | | | `ssh root@…` 거부 확인 |
| 예: 키 추가에 알림 없음 | 지속성 탐지 규칙 (`detections/linux/new-systemd-service.yml` 등) | 6-8 | | | 스테이징 훈련에서 알림 도착 |
| 예: 서버에 장기 DB 비밀번호 | 시크릿 관리, 짧은 자격 증명 | 5-3 · 6-7 | | | |
| 예: 탐지까지 8일 | 이상 징후 알림 (계정별 조회량 등) | 6-2 | | | |

## 5. 재현 확인 (과제를 닫는 조건)

설정 파일을 읽는 것보다 공격자가 쓴 길을 **직접 다시 걸어 본다**. 이 재현은 다음 모의 훈련 시나리오가 된다.

```bash
ssh -o BatchMode=yes root@server.example.com                                  # Permission denied (publickey)
ssh admin@staging.example.com 'sudo touch /etc/systemd/system/ir-drill.service'
ssh admin@staging.example.com 'tail -1 /var/log/alerts.log'                     # new-systemd-service 알림
```
